## F. Package sweep (src/ambo, every module read, every public def grepped)

**Bugs**

27. `src/ambo/optimize.py` line 381: `n_per_draw = max(200, int(dec.get("per_draw_optimisations", 200)))`.
    Any config value below 200 (the only direction a smoke run would tune) is ignored.
    Action: drop the `max`.
28. `src/ambo/optimize.py` lines 214-215, `apply_decision_rule`: when every channel is
    held and the total exceeds current spend, the loop breaks without re-solving, so
    `x` keeps the increases that just failed the ROAS rule and the reallocation table
    shows `recommended_spend > current_spend` on channels flagged `held_by_rule`.
    Action: reset `x = rs.current.copy()` before that break, or let `_solve` run.
29. `src/ambo/optimize.py` lines 48-52: `ResponseSet.carry` defaults to None and is
    replaced by zeros, so a set built without carry silently returns contribution 0.
    Action: raise in `__post_init__` when carry is None.
30. `src/ambo/synth.py` lines 90, 162, 270: the generator hard-codes 52.18 weeks per
    year and derives Fourier order from `len(seasonality) // 2`, ignoring
    `config["model"]`. The `period` parameter of `fourier_terms` is dead. Setting
    `fourier_order: 3` makes `evaluate.py` lines 65-69 raise IndexError. Action: pass
    the config period through and assert `len(seasonality) == 2 * fourier_order`.
31. `src/ambo/optimize.py` lines 384-385: scenario names `same_total` and
    `plus_25_percent` are hard-coded; renaming keys in `decision.scenarios` raises
    KeyError. Action: read them from config or document them as required.
32. `src/ambo/optimize.py` line 364 and `run.py` line 152: Layer D locates Layer R
    output through `config["output_dir"]`, so `--out` passed to layer_r is not honoured
    by layer_d, and `--data` is silently dropped for layer_d.
