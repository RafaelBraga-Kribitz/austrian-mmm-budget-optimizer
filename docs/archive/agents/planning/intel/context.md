## Topic: External dependency — the private agency drop, not an API

- note: The tasking that commissioned the blueprint mentions an ENTSO-E API token. ## Topic: Execution protocol for an implementing agent
- source: docs/EXECUTION_BLUEPRINT/00_MASTER_PLAN.md §4, §8
- note: Seven steps — find your task in 02_WBS (first open task whose dependencies are complete); check the Definition of Ready; read the module contract for every file you touch plus any linked deep dive; implement under the quality standards, patterns, and anti-patterns with tests in the same commit and docstrings carrying `Implements: <REQ-IDs>`; validate using the task's method and the relevant gates; close against acceptance criteria plus the global Definition of Done, ticking the milestone checklist in the PR (one milestone equals one PR, conventional commits with REQ IDs within it); log a line in the append-only `docs/BUILD_LOG.md`. Stop-and-ask triggers are permission and private-data matters, elicitation content, unexplainable gate failures after two attempts, sampler pathologies after the full ladder, the degradation decision, Power BI, and golden-band regeneration. Ground rules agents break most: never implement before git init; never let simulate and model import each other; never commit anything derived from the private drop except stage-2 outputs; never report a number without its HDI or outside SSOT; never widen a gate without an ADR naming the suspected structural cause; never rewrite git history, not even to fix a mistake.

## Topic: Nine execution phases P0-P8 and their milestone mapping
- source: docs/EXECUTION_BLUEPRINT/01_PHASES.md
- note: P0 Repository foundation (M0, 0.5 d, not drop-blocked); P1 Ground-truth simulator (M1, 1.5 d); P2 Warehouse DuckDB+dbt (the M1→M2 seam, counted against M2's 2 d, given its own phase because AD-030 makes it a hard prerequisite of the model, which the Charter's milestone table leaves implicit); P3 MMM on S-A (M2, 2 d including P2); P4 Recovery suite (M3, 2.5 d — passing this phase unlocks all Layer R work under Charter E-2); P5 Agency intake (M4, 1.5 d, human-heavy, partially drop-blocked); P6 Layer R fit plus sensitivity (M5, 2 d, fully drop-blocked); P7 Decision layer (M6, 2 d, code not blocked but Layer R runs are); P8 Reporting and release (M7, 2 d, Layer R content blocked). Any phase exceeding 2× its budget triggers a stop plus an ADR analyzing why. Standing rules: every phase closes with the verification protocol run, the milestone checklist ticked in the PR, a BUILD_LOG entry, and SSOT regenerated if any number changed; a phase is not entered until the previous phase's PR is merged with all CI jobs green; cross-phase parallelism is allowed only along explicitly parallel tracks; any gate widened, dependency added, or spec deviated requires an ADR before merge.

## Topic: Per-phase entry, exit, and rollback conditions
- source: docs/EXECUTION_BLUEPRINT/01_PHASES.md P0-P8
- note: Each phase specifies goals, entry criteria, exit criteria expressed as named gates, deliverable task ranges, quality gate classes, and a rollback condition. Load-bearing rollback rules: P0 — if toolchain choices fail on Windows, fix within P0 and do not defer. P1 — if SIM-072 plausibility fails structurally, do NOT tune the SPEC-01 §4 values; re-check the implementation first, because the spec's parameter set is designed to pass, and only a proven spec-level infeasibility justifies an ADR plus a human spec fix. P2 — any mart schema change after P3 starts is an ADR-worthy contract break. P3 — MD-071 failure triggers the MD-073 ladder in order, one rung per attempt, with rung 4 being a model-class change requiring all of P4 to be rerun; two failed root-cause attempts means stop and ask the human. P4 — a red VR-3xx gate is a stop condition, not a tune-the-gate condition. P5 — permission unconfirmed by end of M4 triggers the Charter §7 degradation ADR now, not later. P6 — wide HDIs are not failure, they are content. P7 — a DC-401 regret failure with a green P4 means suspect the optimizer first, since the model already passed recovery. P8 — if Layer R died in P5, P8 executes the alternate framing and never blocks on Layer R.

## Topic: Traceability discipline
- source: docs/EXECUTION_BLUEPRINT/13_TRACEABILITY_MATRIX.md
- note: Bidirectional matrix — forward (task → REQ IDs → Charter refs → key artifacts) for all 46 tasks T-001..T-806, and reverse (every SPEC requirement family → covering tasks → gaps). The governing rule is that nothing exists without traceability: a PR whose changes map to no REQ ID is either a blueprint bug or scope creep. Reverse coverage verdict: every requirement family in SPEC-01..09 maps to at least one WBS task, and every WBS task cites at least one requirement; the only intentionally uncovered spec content is out-of-scope by charter (O-1..O-8) and the deliberately-does-not-exist list. Recorded residual gaps are all human-dependent rather than structural: AG-001/002 (permission), MD-060..062 (elicitation content), RB-401..406 (Power BI), and AG-040..045 (pending the BP-D-11 decision at ADR-003). Maintenance rule: when a task is re-scoped or an ADR deviates from a spec, the matrix row, the task card, and (if the public API changed) the module contract are all updated in the same PR; a stale traceability matrix is treated as a failed Documentation Gate at the next milestone.
