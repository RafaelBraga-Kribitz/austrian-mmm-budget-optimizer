## Trust Boundaries

The Makefile executes shell recipes and the README is published text. No untrusted input crosses
either.

| Boundary | Description |
|----------|-------------|
| Makefile recipes → local shell | Recipes run with the developer's privileges; a target that silently does nothing is the real risk, not injection |
| README → public readers | Published text; a premature number here would be an unsourced claim |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-19 | Tampering | silent no-op make targets | high | mitigate | Every unimplemented target exits non-zero with the D-27 message; the acceptance criteria assert non-zero exit for all twelve stubs, so a target cannot report success by doing nothing. This is the loud-stub control the milestone gate depends on |
| T-01-20 | Elevation of Privilege | `make all` triggering an unbudgeted fit | medium | mitigate | `all` guards on the presence of posteriors and exits non-zero with instructions before any sub-target runs; `make -n all` is asserted to show no fit invocation (BP-D-20) |
| T-01-21 | Tampering | shell selection on Windows | medium | mitigate | `SHELL` and `.SHELLFLAGS` are pinned in the file rather than inherited, so a developer's personal shell preference cannot change recipe semantics; RESEARCH.md Pitfall 2 forbids installing an MSYS2 Make lineage in CI for the same reason |
