`read_mmm_input(layer: str) -> pd.DataFrame` opens a read-only connection, executes a parameterized
query selecting the seventeen contract columns by name (built from `_contract_columns`, so the
projection and the check share one source) from `fct_mmm_input` for the given layer, ordered by

Validate with a single `violations: list[str]` accumulator, appending one entry per failed assertion
and raising exactly once at the end with all of them joined — never returning early on the first
failure. D-10 exists because a single join bug can trip four assertions at once, and Phase 5's VR-310
debug ladder is what reads the resulting message; peeling violations off one run at a time is the
wrong ergonomics for that moment. The checks, each producing a message naming the layer and the
offending detail:

  - the frame is non-empty; an empty result for a layer that exists in `dim_layer` is a violation,
    not a valid answer;
  - the column names and order match `_contract_columns('fct_mmm_input')`, via `_check_columns`;
  - `week_start` is strictly increasing — report the offending index positions, not just the fact;
  - every consecutive `week_start` difference is exactly seven days — report the offending weeks;
  - no spend column contains NaN — report which columns;
  - `revenue` is strictly greater than zero on every row — report the offending weeks.

Before validating, resolve an unknown layer explicitly: query the distinct layers from `dim_layer`
and, if the requested layer is absent, raise `DataContractError` listing the valid layers. This is
03_MODULES §1.3's named failure mode, and it must produce a helpful list rather than an empty frame.

`read_platform_reported(layer: str) -> pd.DataFrame` follows the same shape against
`fct_platform_reported`, ordered by `week_start` then `channel` so the returned order is total and
stable even though the grain has three keys. Its postconditions are the column-set check, the
unknown-layer check, the non-empty check, and `not_null` on the three grain columns. It must NOT
assert non-null on `platform_conversions`, `platform_conv_value` or `impressions` — those are
legitimately NULL for offline channels, and coercing or rejecting them would destroy the distinction
plan 03-06 preserved.

`read_dim_layer() -> pd.DataFrame` returns all rows of `dim_layer` ordered by `layer`, checking the
column set and that the frame is non-empty. It takes no layer argument.

Every accessor's docstring states its grain, its ordering guarantee, and its postconditions, and
carries the `Implements: AD-030` marker so the requirement is greppable (AGENTS W-1). No accessor
message may contain private-drop content or path — the `AmboError` redaction invariant applies here
even though today's data is Layer P.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| warehouse file to application code | The AD-030 doorway; every frame crossing it is schema- and range-checked before any caller sees it (ASVS V5) |
| `connect()` to callers | The read-only default is the access-control mechanism; the only write path to the warehouse is `dbt build` (ASVS V4) |
| `layer` argument to SQL | A caller-supplied string reaching a query; passed as a bound parameter, never interpolated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03-26 | Tampering | Application code writing to the warehouse and invalidating the dbt-built contract | high | mitigate | `connect(read_only=True)` by default, proven by `test_read_only_connection_rejects_a_write` which also asserts the warehouse is unmodified after the rejected write; the plan 03-02 guard test keeps `model`/`decide`/`report` from opening duckdb at all |
| T-03-27 | Tampering | SQL injection through the `layer` argument | medium | mitigate | The layer is passed as a bound query parameter, never string-interpolated; an unknown layer is rejected against the `dim_layer` list before the query runs. Canon injection guidance applies and is not restated here |
| T-03-28 | Spoofing | A silently wrong frame reaching the model — wrong columns, a gap, a NaN, a non-positive revenue | high | mitigate | Four postconditions checked on every call with the expected column set derived from the dbt contract yml rather than restated; all violations collected and raised once so a multi-symptom failure is diagnosable in a single run (D-10) |
| T-03-29 | Repudiation | A contract test silently skipping because the warehouse is absent | medium | mitigate | No test in `tests/unit/test_db.py` skips on a missing warehouse; the absence produces a `DataContractError` failure naming the transform command |
| T-03-30 | Information Disclosure | A `DataContractError` message carrying private-drop content or path | medium | mitigate | The `AmboError` redaction invariant, restated in `DataContractError`'s docstring (plan 03-02); accessor messages carry weeks, columns and counts, never row values or file paths outside the repository |
