<objective>
Add the `DataContractError` exception the warehouse accessor layer will raise, and convert the
AD-030 mart-only rule from a one-time grep into the fifth standing architectural guard test
(D-09), joining the four established in Phase 1's D-23.

Purpose: T-204 AC-1 as originally written is a grep run once in Phase 3 — it decays the moment
Phase 4 writes the first line of model code, and AD-030 is the constraint the entire "the model
reads a contract, not a pile of CSVs" claim rests on. A standing guard is the only form of that
rule that survives its own phase.

Output: `DataContractError(AmboError)`, `tests/unit/test_mart_only_access.py`, and the
`docs/MODULE_CONTRACTS.md` update the layout guard already demands.

This plan runs in wave 1 alongside plan 03-01 because it touches no `dbt/` file, invokes no
`dbt build`, and therefore takes no DuckDB write lock. Keep every verification command in this
plan scoped to its own two test files — do not run the full suite while 03-01 is mid-flight.

Standing obligations (D-18, D-19): tests ship with what they verify; a shed is written into
`docs/BUILD_LOG.md` before it is carried out. The mart-only guard test is on the D-19
**never-shed** list.
</objective>

  <action>
Create `tests/unit/test_mart_only_access.py` as the fifth standing guard, matching the four
existing guards' structure exactly: module docstring naming the rule and its traceability
(`Implements: AD-030, G-ARCH`), `from __future__ import annotations`, `import ast`,
`from pathlib import Path`, module-level frozen constants, offender collection into a list rather
than failing on first hit, one joined assertion message, and a trailing scan-count print.

Define two module-level constants. `_FORBIDDEN_IO_CALL_NAMES` holds the call names that constitute
a direct data read: `read_csv`, `read_parquet`, `read_csv_auto`, `read_json`, `read_table`.
`_FORBIDDEN_DATA_PATH_PREFIXES` holds the repository-relative path prefixes that are off-limits
outside the accessor: `data/synthetic`, `data/real_anon`, `data/warehouse`, `data/cache`.

Write three scan helpers. `_py_files(base)` returns the sorted `.py` files under a directory,
returning an empty list when the directory does not exist. `_forbidden_calls(tree)` AST-walks for
`ast.Call` nodes whose function is either an `ast.Name` in `_FORBIDDEN_IO_CALL_NAMES` or an
`ast.Attribute` whose `attr` is in that set, plus any `ast.Attribute` call of the form
`duckdb.connect`; it returns the offending names with line numbers. `_forbidden_path_literals(tree,
prefixes)` walks `ast.Constant` string nodes for any value beginning with one of the given
prefixes, in either forward-slash or backslash form.

Write four tests, each taking `repo_root: Path`.

`test_model_and_decide_never_read_data_files_directly` scans `src/ambo/model/` and
`src/ambo/decide/` with both helpers (call names, and all four forbidden path prefixes) and
asserts the offender list is empty. The failure message names the rule (AD-030: model and decide
code reaches data only through `ambo.common.db`) and lists `path:line: offender` entries.

`test_only_db_module_opens_duckdb` scans every `.py` file under `src/ambo/` except
`src/ambo/common/db.py` for a `duckdb` import or a `duckdb.connect` call, and asserts the offender
list is empty. `src/ambo/common/db.py` is the single permitted home; the test must skip it by exact
relative path, not by a substring match.

`test_report_may_read_exports_but_no_other_data_directory` scans `src/ambo/report/` with
`_forbidden_path_literals` using the four `data/` prefixes only, and asserts the offender list is
empty. Add an inline comment stating that `exports/` is deliberately absent from the forbidden
prefix set because 03_MODULES §10 grants `report/` that access legitimately, and a repo-wide ban
would be wrong.

`test_guard_detects_a_known_offender` is the non-vacuity proof and the reason this guard is
trustworthy today. `src/ambo/model/`, `src/ambo/decide/`, and `src/ambo/report/` do not exist yet —
their owning phases are 4, 8, and 9 — so the three tests above legitimately scan zero files. Rather
than letting them pass on nothing, this fourth test writes three synthetic offender modules into
`tmp_path`: one calling a pandas CSV read, one calling `duckdb.connect`, and one containing a
string literal beginning with a forbidden data path prefix. It then runs the same three helpers
over them and asserts each helper reports at least one offender, with a failure message stating
that a detector which finds nothing in a known-bad input is broken, not passing. Once Phase 4 lands
`src/ambo/model/`, the first three tests stop being vacuous on their own; this fourth test remains
the standing proof that the detector fires.

Guard against silent scope loss the same way the other guards do: each of the first three tests
must assert that the scan either found files or that the corresponding package directory genuinely
does not exist yet, and must print a one-line summary naming how many files it scanned, so a future
directory rename cannot quietly reduce the guard's coverage to zero without anyone noticing.
