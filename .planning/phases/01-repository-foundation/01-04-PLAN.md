Create `src/ambo/common/logging.py` exporting `LOG_FORMAT`, `PrivatePathFilter` and `get_logger`.

`LOG_FORMAT` is the fixed structured format from the module contract:
timestamp, level name, logger name, message — as a stdlib `%`-style format string. Document it in
the module docstring as fixed, since downstream log parsing depends on it.

`PrivatePathFilter` subclasses `logging.Filter`. Its `filter()` reads the resolved private-drop
path from `load_settings().private_drop`, never from the environment directly, so there is one
resolution path. When that value is `None` the filter is a pass-through no-op returning True
unchanged. When it is set, the filter replaces every occurrence of the resolved path — matched
case-insensitively on Windows and with both separator forms normalized — with the token
`<PRIVATE_DROP>`, rewriting `record.msg` and every element of `record.args`, then returns True.
Runtime behavior is redact-and-emit, not drop-and-raise; the tests assert that the redaction
happened, which is the WBS's stated choice.

`get_logger(name)` returns a `logging.Logger` for `name`, attaching `PrivatePathFilter` and a
`StreamHandler` formatted with `LOG_FORMAT` exactly once per logger regardless of how many times it
is called, and sets the level from the `AMBO_LOG_LEVEL` environment variable defaulting to INFO.
This factory is the only sanctioned logger-construction pattern; the module docstring states that
`src/` contains no direct standard-output writes.

Create `tests/unit/test_logging.py` covering both environment states with a fake, clearly-fictional
drop path — never a real one, and never the developer's actual value. With the fake path set:
emit a record whose message embeds that path and assert the captured output contains the redaction
token and does **not** contain the fake path; repeat with the path passed through `record.args`
rather than the message. With the variable unset: assert the record passes through byte-identical.
Also assert the fixed format string is applied, and that calling `get_logger` twice with the same
name does not duplicate handlers. Clear `load_settings`'s cache between the two environment states
so the second state is genuinely re-resolved.

Add the grep-shaped invariants as tests here rather than as manual checks: walk `src/ambo/` and
assert every `logging.getLogger` call site is inside `common/logging.py`, and that no module under
`src/ambo/` writes to standard output directly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `config/settings.yaml` → `Settings` | The only structured input this phase parses; an unknown or malformed key must be rejected loudly rather than silently ignored |
| environment (`.env`, `AMBO_PRIVATE_DROP`) → process | The one environment variable the project reads; its value is a path whose contents are secret |
| process → log stream / CI output | Log output is the cheapest way for a private path to reach a CI log or a committed report |
