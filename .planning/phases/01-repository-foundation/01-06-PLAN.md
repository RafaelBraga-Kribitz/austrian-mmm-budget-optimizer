Module constants: `YEAR_RANGE` covering ISO years 2019 through 2027 inclusive; `SEED_PATH` pointing
at `dbt/seeds/season_windows.csv` resolved relative to the repository root rather than the current
working directory; `JAN_DIP_WEEKS` as ISO weeks 2 through 5; `SPRING_WEEKS` as 14 through 22;
`SUMMER_LULL_WEEKS` as 29 through 33.

`advent_weeks(year)` returns the four ISO `(iso_year, iso_week)` pairs for that calendar year:
locate the ISO week containing December 24, take its Monday, and step back 7, 14 and 21 days,
deriving each pair from the resulting date with `date.isocalendar()`. Do the arithmetic on dates,
not on week numbers, so an ISO-year boundary can never produce a week 0 or a wrapped number.

`schulbeginn_weeks(year)` returns the two pairs for the ISO week containing the second Monday of
September and the week before it, derived the same way. Head this function with a source comment
that is explicit about its status: SPEC-01 section 2.1 says "around Styrian school start", the
`holidays` package carries no AT-6 school calendar, and the fixed rule "second Monday of September"
is therefore an interpretation filling a gap the spec left open — not a spec change. Cite the guide
section and note that the record lives in `docs/BUILD_LOG.md` per D-07.

Add a second source comment on the advent rule recording the same kind of reading: SPEC-01's "the 4
ISO weeks before and incl. the week of Dec 24" is read as four flagged weeks total, ending at the
December-24 week inclusive, per the guide.

`build_rows(year_range)` produces one dictionary per ISO week of every ISO year in range, with keys
in this exact order: `iso_year`, `iso_week`, `week_start`, `advent_flag`, `schulbeginn_flag`,
`jan_dip_flag`, `spring_flag`, `summer_lull_flag`. Enumerate the weeks by walking Mondays rather
than by assuming 52 weeks, so ISO years with 53 weeks are complete. `week_start` is that ISO week's
Monday as an ISO-8601 date string. Flags are the integers 0 and 1, never booleans and never blanks.

`main()` writes the seed and returns an exit code. Determinism is the contract here, so be explicit
about every source of byte drift: open the file with an empty newline argument and set the CSV
writer's line terminator to a bare newline so Windows does not emit carriage returns; write the
header row from the key order above; write no index column; sort rows by `iso_year` then
`iso_week`; and emit no trailing blank line beyond the final record's terminator. The
`.gitattributes` pin from plan 01-01 also normalizes this file, but the writer must not rely on it,
because the diff-check in CI job 1 compares the working tree before git's filters run.

Import `holidays` and use it where the Austrian public-holiday calendar is genuinely needed; if the
five window rules turn out to need no holiday lookup, do not import it for appearance — say so in
the module docstring instead, and note that the Phase 2 simulator is the consumer that will need it.

Run the script, commit the generated seed, then run it a second time and confirm `git diff` is
empty before the task is done.
